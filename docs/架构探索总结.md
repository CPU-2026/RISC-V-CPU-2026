# 架构探索总结

> 依据：[process.md](process.md)，整理范围为 2026 年 8 月底至 11 月 7 日。本文按架构问题归纳探索过程与取舍，不替代逐次实验记录及认证证书。所有历史增减幅均相对该实验当时的基线，不可直接相加。

## 一、探索目标与最终结果

本项目从 RV32IM 软件原型出发，逐步建立具有明确时钟沿语义的乱序处理器模型，再将其实现为 RTL。开发重点不是单纯增加发射宽度或缓存容量，而是在**功能正确、逐拍一致、IPC、频率和面积**之间寻找可验证的平衡。

评价标准随开发阶段演进：早期关注功能与容量代理，之后转向完整顶层综合和静态时序分析；面积约束也经历过调整。最终采用的目标为：

- 面积严格小于 **36000 μm²**；
- Fmax 估计大于 **300 MHz**；
- 原六项测试的几何平均 IPC 大于 **1.0985**；
- 同时记录评分 `IPC⁴ × Fmax / Area²`，但评分不能覆盖面积、频率等硬约束。

截至 11 月 7 日，正式生产采用跨 16B 边界四取指，主要配置如下：

| 部分 | 最终采用配置 |
|---|---|
| 前端与退休 | fetch/decode/rename/commit = 4/4/4/4；最多连续取 4 条，允许跨 16B，但不跨 64B I$ 行 |
| 执行与写回 | 双 ALU、三条 CDB；保留单 AGU，不等同于四路整数或四路访存执行 |
| 在途容量 | FQ8、IQ8、ROB32、PRF64、checkpoint64 |
| 缓存 | I$ 1 KiB；D$ 8 KiB、两路、32B 行；D$ 8 请求槽、4 MSHR |
| 关键机制 | 标准 RAS 分类、Load 下一行预取、安全 Load 让行、SQ 完成事件旁路、LSU 通知资格提前计算 |

| 最终认证指标 | 数值 |
|---|---:|
| 面积 | 34947.061567 μm² |
| Fmax 估计 | 319.301528 MHz |
| 原六项几何 IPC | 1.137201912621 |
| 评分 | 4.372501753378e-7 |

三项目标均通过，面积剩余约 1052.94 μm²。这里的 Fmax 是统一理想时钟、无寄生约束下的整核 STA 估计，**不是后布局频率**；IPC×Fmax 仅用于吞吐估算，不是墙钟实测。整体几何 IPC 达标，也不代表每个测试都达到 1.0985。

## 二、从软件模拟器到硬件式周期模型

### 2.1 先约束时序语义，再扩展并行性

早期软件原型已有 RAT、PRF、ROB、LQ/SQ、缓存和分支恢复，但软件函数调用顺序容易引入硬件中不存在的隐含旁路。例如，某模块先更新结果，另一个模块随后读取，就可能在同一软件周期中提前使用新值。

为此，开发中迁移到 `Register/Wire/work()/sync()` 风格，统一“读拍初状态、写拍末状态”的语义。后续主软件树坚持只读旧快照和 Input、逐字段写目标；模板树坚持 Register 单写和统一 sync。只有明确设计并授权的组合旁路，才能在当拍传递数据或信用。

同时统一 `epoch + slot` 完整 ROB tag，避免仅用物理槽号判断返回归属。分支取消后槽位可以重用，但旧结果、旧访存响应不能污染新指令。

**取舍：**严格的周期合同增加了接线、身份管理和验证工作，却使软件模型能够预测 RTL 行为；不能为了让软件跑得更快而接受执行顺序造成的“免费旁路”。

### 2.2 正确性从“答案相同”升级到“事件与周期一致”

三端对照逐步覆盖软件主树、模板树和 RTL 的握手、分配、写回、退休及恢复，而不只比较最终答案。关键合同包括：

- LQ 在真实退休后释放；SQ 已提交项在真实内存接受后释放。
- 转发要求单一 Store 完整覆盖 Load，不拼接多个来源的字节。
- 普通写回拍捕获、下拍依赖派发；当拍派发属于单独验证的旁路机制。
- 恢复选择最老事件，完整身份贯穿取消、重放和返回。

早期曾验证 18 ISA＋6 IPC 的逐拍与最终内存一致，但当时尚未接课程 AXI。课程接入后，退出语义改为退出 Store 退休时冻结核心、对应 B 握手结束计时，不再要求 HALT 后扫描排空全部 dirty 行。**结束协议变化后，旧周期不能直接用于新版本比较。**

功能域也曾主动收窄到合法 RV32IM、对齐控制转移输入，删除异常检测、传播和 trap 状态。这是支持范围的取舍，实测却未天然改善 PPA；不能把“少支持功能”直接等同于面积、频率必然更优。

## 三、宽度探索：供给、执行与退休必须分开优化

### 3.1 由单宽逐步走向四宽

开发没有一次性复制整条流水线，而是按退休、取指、译码、重命名、执行和写回分别扩展：

| 阶段 | 主要探索 | 结论与代价 |
|---|---|---|
| 双提交 | ROB 消费连续旧 ready 前缀，RAT/PRF/LSU/RAS 共同处理退休 lane | 降低退休瓶颈，但不增加前端供给与整数执行能力；本拍写回不直接旁路退休 |
| 双取指 | 行内预译码、最早控制流截断、单 BPU 查询、逐条 CID | 建立宽前端；早期 IPC 改善并未完全抵消频率代价 |
| 双译码、双分配 | 连续前缀消费、组内 RAW/WAW、LINK 即就绪、双 Load/Store 入队 | 同配置几何 IPC 约 0.660200→0.735362，但首次面积超过当时上限 |
| 四译码、四分配 | 统一前缀规划器，数组 RAT/PRF/ROB，七池 RS/LSQ 共用真实 fire | 同时扩到 ROB32/PRF64/CKPT64、FQ8/IQ8；收益包含扩容，不能全归于宽度 |
| 完整四宽 | 四取指与四退休贯通，再比较执行、写回组织 | 必须补足执行和写回带宽，四宽接口本身不保证高 IPC |

10 月 28～29 日的四宽隔离实验中，单 ALU、两 CDB 的 core 周期几何 IPC 为 0.829014；双 ALU 共享整数 CDB 仅升至 0.829644；双 ALU 各自拥有 CDB、第三路共享 Load/MUL/DIV 后达到 0.859878。结果表明，**增加执行单元而不增加写回能力，会把瓶颈转移到结果出口。**这些数值属于当时的 core 计时口径，不与后续课程退出计时混用。

双 AGU 也做过独立尝试，第二地址确实被交付，但 median 周期不变、六项几何 IPC 略降，因此没有推进该同池批量双地址方案。这里否定的是具体实现，不是证明所有双 AGU 都无收益。

### 3.2 空队列直通：减少排队级数，而不是盲目加槽

后期在固定容量下发现，空 IQ、空 FQ 仍可能形成不必要的中间存储等待，于是分步实现：

1. **空 IQ 整组旁路：**直接展示旧 FQ 的译码组，只有全部有效 lane 都能分配才整组接受，否则零分配并整组入 IQ。
2. **空 FQ 新包直通：**仅旧 FQ/IQ 均空时，新返回包直达译码；实际接受后只消费一次。
3. **Store 地址 RS 写回数据旁路：**旧项可用已授权 CDB 数据派发，但只有实际获得共享 AGU 接受才返还信用。

空 IQ 整组旁路相对当时基线几何 IPC +2.807266%，但面积 +0.387729%、Fmax −1.151515%。随后空 FQ 与 Store 地址旁路另建组合、验证并实测，几何 IPC +2.780824%，面积 +0.223820%、Fmax −3.248120%，评分 +7.489459%；IPC×Fmax 估算却为 −0.557621%。该组合被采用，但并不是所有性能维度都改善。

进一步尝试“只接受连续前缀、后缀压紧入 IQ”的两层部分接受机制，正确性通过，原六周期却完全持平，最终未采用。**更细的接受粒度会增加控制复杂度，只有触及实际关键等待才有价值。**

### 3.3 最终关键突破：解除取指包的 16B 人为边界

11 月 7 日没有套用旧四取指数据，而是在已采用的 LSU 通知提前计算双取指生产上，新建同源三方案对照：

| 测试 | 双取指基线周期 | 16B 受限四取指 | 跨 16B 四取指 |
|---|---:|---:|---:|
| median | 7676 | 7471 | 7620 |
| multiply | 16908 | 17415 | 12379 |
| vvadd | 3984 | 3982 | 3740 |
| towers | 5509 | 5507 | 5477 |
| qsort | 147475 | 149619 | 148089 |
| rsort | 162806 | 159792 | 159739 |
| **几何 IPC** | **1.063329023912** | **1.063797503283** | **1.137201912621** |

仅拓宽到受限四取指，整体 IPC 只增加 0.044058%；解除 16B 限制后，相对受限控制提高 6.900224%。两种四取指之间的比较隔离了包边界影响；双取指与四取指之间还包含宽度及其派生行为差异。

实现利用 I$ 已有的任意 word 起点 128 位滑动数据选择，不新增 SRAM 端口、buffer 或流水级；仍不跨 64B 行、在最早控制流指令处截断，cold 单条、单预测口、逐条 PC/CID 保持。四取指仍采用保守恢复冻结，没有合入双取指专属恢复扩展。

最终相对双取指，面积 +0.713718%、Fmax +0.997817%、几何 IPC +6.947322%、评分 +30.260993%，因而采用。但 qsort 多 614 拍，median 相对受限四取指也多 149 拍，不能称逐项无退化。受限四取指只完成正确性与 IPC 筛选，**没有单独测量 PPA**。

**核心取舍：**先消除已有数据通路上的供给限制，再考虑增加硬件资源；宽度、边界、恢复策略必须分开对照，不能把历史四宽指标移植到当前源码。

## 四、存储系统探索：并发、容量与安全边界

### 4.1 从寄存器缓存到 SRAM、非阻塞缓存

早期软件曾使用大容量缓存，但容量代理不能代表 ASIC 成本。综合发现寄存器 D$ 占面积约 64%，成为转向 SRAM 的直接依据。随后将 valid 与载荷复位分离，并优化地址广播和选择网络。

数据侧进一步引入两路 D$、4 MSHR、合并、hit-under-miss 和乱序返回。LSU 用独立 owner 和持久 drop 状态跟踪真实运输身份，不能靠有序 FIFO 猜响应归属：**取消只是取消架构使用，不代表总线事务消失，也不代表运输信用可以立即释放。**

Load ABC 探索允许旧 hit 消费与下一 lookup 重叠、AGU 地址当拍请求、合法返回当拍参与 CDB，IPC 得以提升；初版却形成 SQ→I$ 片选长链，频率仅约 232.52 MHz。将 I$ 物理使能提前、迟到返回从宽仲裁中提出、资格比较提前共享后，在不加流水级下收敛到约 322.93 MHz。代价是额外闲置读的潜在功耗，项目未测量这一项。

完整行到达后的 early restart 被保留；critical-word 部分行早返回虽有隔离功能验证，但紧凑候选未通过当时频率/IPC 门槛，没有进入生产。两者不能混为同一优化。

### 4.2 扩容不等于最优：I$、D$ 与 victim cache

以下结果均相对各自当时基线；“仅筛选”不表示已知面积、频率代价。

| 探索 | 测量结果 | 最终取舍 |
|---|---|---|
| I$ 1→2→4 KiB | 2/4 KiB 都仅使 towers 少 46 拍，几何 IPC +0.131343%，4 KiB 无额外收益 | 未做 PPA；决定保留 1 KiB |
| D$ 8→16 KiB | 几何 IPC +5.554513%；新 PPA 面积 38112.641969 μm²、Fmax 314.399754 MHz | 面积超 36000，不采用 |
| D$ 8→32 KiB | 几何 IPC +6.059808%；相对 16 KiB 主要继续改善 rsort | 仅筛选，未测 PPA，未采用 |
| 8 KiB D$＋4 行寄存器 victim cache | 树 PLRU 全相联，几何 IPC +0.133898%；面积 35615.175487 μm²、Fmax 293.157744 MHz | 面积合格但频率失败、评分 −9.118523%；用户明确不采用 |
| Store 命中位置表 2→4 项 | 复用已确认命中 way；几何 IPC +1.025965%，Fmax −3.093102%，评分 −0.471751% | 披露代价后采用；不是增加缓存数据容量，也不是精确 LRU |

D$ 扩容确实降低排序程序的行读与脏淘汰，但 SRAM 数据阵列增长本身占据显著面积。victim cache 虽小，还需要全相联比较、交换、预留和脏行所有权控制，不能只按四行数据估算成本。**命中数、行读减少量和队列满周期都不等于固定可省拍数。**

### 4.3 用限流预取替代直接扩容

设计 Load 预取前，先观察从机：原六中五个 16 项 Slave 队列均未满，也未出现通道容量背压。这支持研究利用空闲服务机会，但不能保证新增预取不争抢带宽或信用。

最终采用“真实接受普通 RAM Load 触发下一条 32B 行”：4 项最近源行去重、单 pending 目标、最多一条显式类型预取；共享原 8 请求槽、4 MSHR 和 2bit ID，需求优先并预留信用。预取不伪造 LSU 身份，所有 CPU 返回路径都排除预取类型。未占 MSHR 的冲突预取可丢弃，已占 MSHR 的事务则必须保留 set 锁、脏 victim、写回和回填所有权。

相对当时生产，几何 IPC +2.458373%，面积 +0.523014%、Fmax −1.979604%，评分 +6.899400%；IPC×Fmax 估算仅 +0.430103%。towers 仍多 10 拍，其余五项改善。

**取舍：**用少量控制状态隐藏部分延迟，而不是增加整块缓存；同时承担流量、污染和排队干扰风险，因此必须限流、需求优先，并以整核结果而非离线预测机会数作判断。

## 五、调度与访存仲裁：提前不一定更快

### 5.1 信用复用只认可真实接受

RS 离站同拍复用可以减少结构性空泡，但共享 AGU 下，Load 获胜不代表 Store 地址 RS 已离站。最终除 MUL/DIV 外的相关 RS 采用实际离站信用复用；新分配写入覆盖旧释放，新项不能同拍派发。

补齐 Store 地址 RS 信用后，几何 IPC +0.169731%，但 Fmax −2.654867%、评分 −1.449979%，披露后采用。相比之下，LQ 释放信用筛选仅提高约 0.005288%，ROB 退休信用完全持平；SQ/LSQ 信用存在单项回退。由此可见，**释放发生得更早只有在上游确实缺信用时才产生收益。**

容量探索也给出反例：仅 Store 数据 RS 从 2 扩到 4、消费仍最多 2 条/拍后，真实占用确实达到 4，但 vvadd IPC −9.018265%、整体 −1.461943%，最终被明确否决。不能把“出现背压”直接解释为“加槽即可改善”。

### 5.2 Store/Load 让行必须同时保证消歧和公平性

原有 Store 优先策略可以保护顺序与避免饥饿，但也会延迟无关 Load。简单翻转优先级不安全：已提交待发 Store 的重叠依赖原先发送顺序，不能只检查未提交项或队首；SQ 出队也必须使用真实 Store grant，不能仅更换请求 payload。

探索因此逐步收敛到：检查全部待发 Store 的字节关系，只允许原最老合法 Load 有界越过，一次真实 Load 接受后强制真实 Store 接受，债务跨 flush 保持。

| 策略 | 相对当时生产的几何 IPC | 观察与决定 |
|---|---:|---|
| 不加压力门控的单次让行 | +0.018131% | qsort 改善被 vvadd/towers/rsort 回退大幅抵消，未采用 |
| SQ≤2、owner=0 | +0.403630% | 限制压力后改善，但仍有多项回退，未采用 |
| SQ≤1、owner=0 | −0.105459% | 未采用 |
| SQ≤4、owner=0 | +0.759869% | 有限参数集合中最高；rsort 多 2262 拍，其余五项改善，完成 PPA 和软件资格后采用 |
| SQ≤2、owner≤1 | +0.685337% | 未采用 |

采用的 SQ≤4/owner=0 版本面积 +0.259469%、Fmax +2.364139%、评分 +4.965701%。这里 owner 包括取消后尚未真实返回的运输事务；owner=0 也不等于 Cache 完全空闲。

早期 rsort 仲裁还揭示了局部指标的误导性：一个关键 PC 的队首等待少 27269 拍，后续两个 PC 的等待却显著增加，全体队首 Load 等待只少 28 拍，整核反而退化。**等待位置迁移不能算作瓶颈消失。**

### 5.3 全核仲裁与合格 Load 选择的收益边界

仲裁筛选不只覆盖 LSU，还独立测试 AGU 偏向、共享 CDB、AXI AR 权重、Cache 查询和需求 miss 发送，共九项。最高为 AXI AR I:D=2:1，几何 IPC +0.142158%，但仍有单项多 1 拍；AGU 两种偏向反而下降约 0.66%/0.80%，CDB 和 miss 发送偏向持平。这些方案均未综合、未采用，也未与后续方案自动组合。

“先过滤阻塞项、选择最老合格 Load”也通过正确性验证，但整体 IPC 微降约 0.000108%，未改善最弱项，最终被明确否决。更多选择逻辑并不必然换来整核性能。

## 六、分支预测与恢复：先修语义，再谈容量

早期尝试过 TAGE、Tournament、间接 Target Cache，以及局部历史和计数器组织。TAGE→Tournament、删除当时语料无收益的间接目标缓存，是针对当时工作负载的成本取舍，不代表普遍优劣。后续采用真实 Tournament，并在 checkpoint 中保存预测时局部历史及分量预测，不能用解析时的新上下文替代训练上下文。

BTB SRAM 化也曾尝试：单 SRAM 改四 bank、tag/target 分离后，还需预测汇合、训练 FIFO/credit 和取消逻辑，面积收益抵不过当时 IPC 损失，课程路径恢复寄存器 BTB。**SRAM 化的成本不仅是阵列，还包括端口、同步读时序与旁路。**

RAS 是“先诊断再扩容”的典型案例。towers 的 68 次真实函数返回中，仅 34 次使用 RAS，但使用时全部正确；投机/架构峰值深度均为 1，而容量为 8，因此不支持先加深栈。最终定位到同 link JALR 分类，修正为：

```text
pop  = rs1Link && (rd != rs1)
push = rdLink
```

即同 link 只 push，异 link 才 pop 后 push。保持容量与恢复节奏后，towers 少 372 拍、multiply 少 413 拍，几何 IPC +1.509617%；qsort 多 1 拍，Fmax −0.306091%，仍经验证后采用。

恢复本身也有面积/周期取舍：提交 RAT/RAS SRAM 化及四拍恢复节省面积，但引入恢复开销；双取指阶段曾允许经过鉴权的安全非控制响应在恢复期间运输、推进，后端仍冻结。该扩展并未不加区分地移植到最终四取指，后者保留保守恢复冻结，以控制恢复正确性的复杂度。

## 七、面积与关键路径：逻辑等价不等于物理等价

### 7.1 载荷复位分离与 SRAM 化的边界

控制位通常必须复位，而受有效性保护的数据载荷未必需要逐位复位。但 ROB 还存在失效端口载荷和取消项 replay，不能仅因 valid=0 就丢弃历史表示。

11 月 4 日从同一基线独立比较四项结构，原六周期和几何 IPC 均保持不变：

| 独立候选 | 面积 μm² | Fmax MHz | 评分相对变化 | 取舍 |
|---|---:|---:|---:|---|
| PRF 上一拍转发共享 | 34683.207307 | 307.322929 | −0.074542% | 收益不足，未采用 |
| PRF 读译码重组 | 34754.824267 | 308.526665 | −0.096156% | 实际未省面积，未采用 |
| ROB 载荷复位分离 | 34238.371507 | 313.341493 | +4.546957% | 省 468.382500 μm²，同时提频，采用 |
| ROB 单行 SRAM 载荷 | 33700.451751 | 268.414155 | −7.561337% | 更省面积但频率失败，未采用 |

ROB 复位分离保留 valid/ready/完整 tag 控制复位，以每行 initialized 屏蔽未初始化读；initialized 不随 valid 清除，从而保留历史载荷合同。ROB SRAM 候选则额外付出 32 个 1×129 宏和共享最近写记录，说明多端口、当拍读取与最近写转发会抵消阵列本身的优势。

PRF 的成功路径是值载荷微银行 SRAM 化及共享写优先级仲裁；更激进的重定时虽然提频，但面积过大，未被接受。LQ 结果去复位的独立专项甚至面积略增，提醒我们**综合器映射会改变预期，删除复位不能只靠源码估算收益。**

### 7.2 晚到身份选择比“全面并行化”更值得实测

关键路径分析曾发现 AXI/Load/CDB、RS 信用、重命名和 PRF 之间的跨模块依赖。优化必须结合完整顶层 STA，而不是把 generic 网表最长门数链当成可敏化时序路径。

- **PRF 并行分配排名：**局部和原六周期完全保持，但整核 Fmax 降至 280.317547 MHz，评分 −7.058581%，用户明确不采用。
- **ROB 独立 Load lookup 行并行身份校验：**保留 stored tag、常数行、query 槽和 epoch 的完整认证；IPC 不变，面积 −0.273049%、Fmax +5.377681%，采用。
- **ROB 普通 lookup 并行校验：**看似类似的改动，实测却仅省 0.030712% 面积，Fmax −1.037652%、评分 −0.976836%，未采用；不将建议不采用写成用户明确否决。
- **LSU 通知资格提前计算：**旧 LQ×SQ 行提前计算范围、年龄及屏障资格，晚到身份只选一位；状态写入、事件语义、完整转发载荷不变。IPC 保持，面积 +0.679820%、Fmax +3.056499%、评分 +1.669462%，采用。

**取舍：**用更多预计算换取更短的晚控制路径有时有效，但复制比较逻辑会增加面积和扇出；“并行”“平衡”“代码更短”都不能代替映射后的整核测量。

## 八、开发中遇到的问题与验证方法

### 8.1 局部优化与整核反馈不一致

multiply 实际执行移位/条件加法循环，没有 MUL 指令；若只看程序名称就扩乘法器，会优化错对象。median 的 Store 完成链也显示，SQ 地址/数据已齐并不代表 ROB ready 已更新。SQ 完成事件旁路使 median 少 345 拍、IPC +4.494528%，但四个其他测试回退，整体 IPC 只增 0.366506%，Fmax −2.127022%。该机制仅提前通知 ROB 寄存 ready，仍在后续拍读旧 ready 退休，不能混同于提前写内存或恢复已否决的 Store 地址→Load 数据通知。

因此画像区分真实退休与投机事件、需求与预取、候选与实际 grant、队列满状态与实际背压；任何观察拍数都不直接相加成“可省周期”。

### 8.2 三端同步必须保留原始 proposal 与接受事件

Load 预取软件同步时，两软件答案都正确，但 rsort 比 RTL 少 5 拍。原因是满 Cache 时软件将原始 proposal-valid 隐藏成 accepted-valid=0，错误放行预取 Tag 查询。修正后将 proposal 展示与实际接受分开，才恢复逐拍一致。

SQ 压力计数也曾混用带 epoch 的尾指针和物理头槽，导致模板周期漂移；改为归约旧有效行后通过。两个案例说明，**答案一致甚至两软件一致，都不足以证明 RTL 周期合同正确。**

### 8.3 工具、夹具和资源错误不能伪装成架构结论

- 四宽完整综合曾在展开/TECHMAP 中断，最初误判为重启，后由内核日志确认 OOM。通过隔离资源、分阶段 checkpoint 和降低内存压力解决；未完成阶段不报告有效最终 PPA。
- 大缓存循环展开触发工具限制时，提高展开配置，而不是关闭检查；夹具的 `ref`、默认参数、typed port 等转换问题单独修复。
- SQ 完成 bitmap 与访存请求共用大组合块曾触发工具依赖环；将原方程拆成独立组合锥后再验证，而不是压制 UNOPTFLAT。
- 外部观察器可能引用被优化消除的别名；应修观察器并认证复用原模型，不能为观察方便改变生产逻辑。
- 服务器重启、审计来源标签和路径错误均保留失败记录；只有同一次已认证 checkpoint 才能明确标注接续，否则重新从 elaborate 开始。

### 8.4 建立分层证据，区分筛选、PPA 与采用

后期采用的验证链为：

1. 整核组合环/锁存检查，局部真实模块独立 oracle、公开端口差分及有效 RTL 负向测试。
2. native SystemVerilog 与 sv2v converted 两模型分别运行原六，核对答案、374104 条九字段架构退休及同变体完整日志。
3. 同源完整顶层综合/ABC/STA，独立核算 Liberty 逐叶面积、实际 SRAM 宏、工具库和约束，避免拼接不同版本 IPC 与 PPA。
4. 采用前对两软件做全新 Release/断言四构建及外部退休 PC/周期对照，备份后发布精确源码和正式指针，再做发布后复验。

局部差分、任意旧态检查和负向测试加强了证据，但原六通过**不是任意输入、全部状态的形式等价证明**。同源资格可以按哈希复用，不应冒称重复重建；历史原始产物清理后，也不能声称仍可从旧网表重新审计。

## 九、主要权衡与经验

1. **宽度必须匹配整个通路。**取指、分配、执行、写回和退休是不同资源；最终最有效的前端改动是解除不必要的包边界，而不只是增加 lane。
2. **先观察真实瓶颈，再扩资源。**RAS 分类修复优于盲目加深；SV 扩容和双 AGU 的反例说明资源压力不等于扩容收益。
3. **保持顺序、身份和所有权是优化前提。**取消不能提前释放运输身份，ready 不等于接受，完成通知不等于退休或内存写入。
4. **局部等待减少不等于整核提速。**需同时检查后续排队、分支恢复和其他测试，不能只报告一个 PC 或一个程序的改善。
5. **IPC、频率和面积必须共同衡量。**ROB SRAM、16 KiB D$ 和 PRF 排名分别展示了频率、面积或映射代价；评分更高也不能越过硬门槛。
6. **独立收益不相加，组合要另测。**同源对照隔离变量，组合必须重新验证并实测 PPA；不同 epoch、计时边界和工具流程的指标不能混用。
7. **采用与达标是不同决策。**开发中曾明确接受 IPC 提升但估算吞吐下降的版本，也保留了未采用和被否决方案。最终四取指三项目标通过，只说明其在当前认证集合中表现最优，不证明架构全局最优。

总体上，项目由早期“增加能力”转向“减少供给空泡、修正控制语义、收敛晚到路径”，再以同源整核测量决定取舍。最终结果不是某一个大规模扩容的产物，而是周期合同、存储所有权、前端几何和物理实现共同收敛的结果。
