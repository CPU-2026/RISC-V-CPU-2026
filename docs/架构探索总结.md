# 架构演进史

项目从 2026 年 8 月的 RV32IM 软件周期模型起步，接入课程 AXI4-Lite 总线协议，从标量逐步扩成四宽超标量乱序核，先以 `4603d03` 提交作为生产，随后按课程口径采用 PRF 回收优化。以下是这次架构演进的过程。

## 8–10 月：将暑假完成的 CPU 仿真模拟器逐步完善成 RV32IM 的硬件核心

软件原型已经具备重命名、乱序执行和按序退休，但函数调用顺序会让后调用的模块提前看到同拍新值。项目改用 DarkSharpness 的模板，采用拍初读旧状态、拍末统一更新的硬件语义。架构主要发生了如下变化：
1. 采用 PRF 物理寄存器堆代替原来的逻辑寄存器副本，减少数据的搬运；
2. 采用 LQ、SQ 分离的架构代替原来 LSQ 耦合架构，分散职责；
3. ROB 用包含年龄位（epoch bit）和物理槽号的完整 tag 区分指令；
4. 使用手写的 Booth 编码、伪华莱士树来实现乘法，使用手写的 SRT-4 Radix 来实现除法；
5. 带寄存器 D$ 的早期实现中，D$ 约占总面积的 64%，于是改用项目自带的 FakeRam 来代替原来由寄存器实现的 D$ 和 I$；
6. 使用 spec-arch 模型和 ROB walk 来完成 RAT、PRF Freelist、RAS 的分支预测恢复；
7. 分支方向预测器由 TAGE 换到 Tournament，这是用简单实现换取面积的 Trade-off；
8. 引入 4 个缺失跟踪项（MSHR）并采用同行合并来实现非阻塞式 D$；
9. 课程版以退出 Store 退休冻结核心、对应 AXI B 握手结束计时，不再执行模拟器的 HALT 的全脏行排空行为。

这一阶段主要是完成单核 CPU 的实现，由于没有进行综合和 perf 的 IPC 测量，没有进行取舍。

## 10 月下旬–11 月 7 日：四宽的难点是供给和写回

超标量实现先做双退休，再扩取指、译码、分配和执行。双退休仍只消费拍初就绪的连续 ROB 前缀；批量分配必须处理组内 RAW/WAW，并让 RAT、PRF、ROB 与各保留站、访存队列按同一实际接受前缀推进。四宽最初用 ROB32／PRF64，后来经过消融实验发现 ROB16／PRF48 的 IPC 仅仅减少一点点，于是我们进行了一个 Trade-off：即用**少量 IPC 损失来换取可观的面积预算**。

我们为了提高 IPC 做了如下架构尝试：
- **执行单元与写回 CDB 的配套。** 10 月末同一 core 计时口径下，单 ALU 为 **0.829014 IPC**；双 ALU 共用整数写回只升至 **0.829644**，两路 ALU 各有写回才到 **0.859878**。于是我们进行了一个 Trade-off：即用**两根 CDB 的面积和频率开销来换取 IPC 收益**。独立双 AGU 试验确实发出了第二个地址，但整体 IPC 略降，并未采用。
- **空队列旁路比无条件加槽直接。** 空 IQ 可让 FQ 的译码组直接争取分配；旧 FQ/IQ 全空时，新取指包也能直达译码。原设计整组接受，否则整组落队列，不能重复消费。再做部分接受和后缀压紧没有减少原六周期，未采用。
- **四取指真正的收益来自去掉人为边界。** 我们进行了多种取指的对照实验：双取指、受限制的四取指、解除限制后的四取指，perf 几何 IPC 分别是 **1.063329／1.063798／1.137202**。两种四取指之间相差 **6.90%**。

## 11 月上旬：先定容量

完成四宽后，我们先做参数实验找容量。14 组配置、6 个程序、168 次对照显示：分配宽度 2→4 只再涨 **1.52%**，vvadd 还退化 **21.15%**；固定 PRF96 时，ROB 16→32 涨 **1.33%**，32→64 涨 **2.76%**；PRF 64→96 在这六个程序上完全没有收益。I$ 1→2 KiB 只让 towers 少 **43** 拍，2→4 KiB 没有额外收益，保留 **1 KiB**。

D$ 是反例最多的地方：8→16 KiB 的 IPC 有 **+5.55%**，但面积 **38112.64 μm²** 超限、Fmax 只有 **314.40 MHz**，不采用；基于 11 月 8 日另一条基线的 16 KiB 版面积 **35107.70 μm²**，曾在限额内采用，但 `Fmax²×IPC/Area` 反而降 **2.27%**，生产后来回到 **8 KiB**。四行 victim cache 面积合格，Fmax 只有 **293.16 MHz**，明确不采用。

最后用限流预取代替扩容：普通 RAM Load 真实接受后预取下一行，IPC **+2.46%**、Fmax **−1.98%**，评分 **+6.90%**，采用。

访存仲裁也做了取舍：Store 通常优先；只有 SQ 占用不超过 4 且无在途 Load 时，合格 Load 才能越过不重叠的普通 RAM Store 一次，随后必须先接受 Store。LQ 按真实退休释放，SQ 按内存实际接受释放；通知、候选和 `ready` 都不能代替真实授权。

`towers` 的返回失配也曾被误认为 RAS 太浅，实际峰值深度只有 1，问题是同 link 的 JALR 应只 push。**容量不是越大越好，先查行为，再找边际，最后用 PPA 决定。**

## 11 月 9–18 日：把预计算从晚授权里拆出来

回到 8 KiB 后，SRAM 先读和延迟展开把新流程基线定在 **316.11 MHz**；这是工具流程变化，不算 RTL 提频。三项组合优化（LSU 相邻字比较、分支旧空位判断、PRF 旧目的 tag 旁带）到 **333.35 MHz**，完整 Load 写回包再到 **346.31 MHz**。候选可以先算，实际 CDB 有效、身份和载荷仍由原获准来源决定。

跨模块反馈更难：后端接受数要经过 IQ 容量、译码数，最后才决定 FQ 能不能接收新包。双队列反向信用把晚算术改成旧态预计算、末级按实际接受数选择，到 **357.34 MHz**。这次按授权采用，但没有达到当时 400 MHz 或全组非退化要求，527 个稳定端点余量退化。

随后形成 Load 独占一路 CDB 的四写回结构，Load／StoreAddr 选择性晚唤醒，Branch 仍不能借 Load 当拍派发；恢复扩到每拍 **8 槽**，RAS 从已提交状态按程序顺序重放。八路 RAS 版在 **2.5 ns** 下是 **427.89 MHz**（同口径 W8／S 为 **399.03／422.27**），同一源码用 **2.0 ns** 重新映射只有 **395.37 MHz**。两者网表不同，不能把差值算作 RTL 收益。
