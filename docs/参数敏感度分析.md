# 参数敏感度分析

> **已完成（2026-11-07）**：14个有限配置、原生／sv2v双模型、每配置6程序，共168次整核运行，答案与九字段架构退休匹配，同配置双模型周期一致。独立 raw 重数审计通过。默认配置周期保持；未综合、未测新面积／Fmax、未更改生产默认参数或正式采用指针。

> **追加 vvadd 画像（2026-11-07）**：复用原资格模型完成 ROB16／ROB32、固定 PRF96 的逐拍对照及一个固定低延迟诊断；详见4.1节。未重跑原168次资格，未改当前生产配置。下文“默认基线”指原参数试验的 ROB32／PRF64，不指之后已采用的 ROB16／PRF48。

## 结论摘要

- **分配宽度1→2最敏感**：固定其他资源的控制组几何 IPC **+25.255892%**，六项均改善；2→4仅 **+1.518489%**，且 vvadd 退化，出现明显边际收益下降。
- **ROB 增大有总体收益，但不是逐程序单调**：固定 PRF96，ROB16→32几何 IPC **+1.333233%**，ROB32→64再 **+2.761857%**；前一段 vvadd 反而退化17.085561%。
- **vvadd 的反常集中在访存时序而非分支恢复**：ROB32多639拍，其中向量加法阶段多642拍；全程队首 Load 等待多680拍。总取行数相同，但预取发起的行读由70降至32，向量阶段预取入队由37降至2。已核验实际准入条件；尚未做关闭预取的消融，不能把全部差异归因于预取。
- **额外 PRF 在当前窗口下没有收益**：ROB32时 PRF64→96六项周期全部不变；补测 ROB16时 PRF48与96也逐项持平。
- **I$ 收益小且较早进入平台**：直接映射1→2 KiB，或固定1 KiB从1→2路，均仅 towers 少43拍，几何 IPC **+0.131453%**；2→4 KiB和2→4路均无额外收益。
- 上述结论只适用于本轮控制条件与六个程序。**不把不同控制组的绝对 IPC 混作单变量收益，也不据 IPC 自动选择生产配置。**

## 1. 分析目标与统计口径

评估顺序分配宽度、ROB、PRF、I$ 容量与相联度对 IPC 的敏感度，区分单参数对照与多参数组合。这里的 `CPU_ISSUE_WIDTH` 是**重命名／顺序分配宽度**，不是执行单元数量；执行带宽另由 ALU、AGU 和 CDB 决定。

六个程序的实际架构退休指令数固定：

| 程序 | median | multiply | vvadd | towers | qsort | rsort |
|---|---:|---:|---:|---:|---:|---:|
| 退休指令数 | 6961 | 21722 | 4524 | 5278 | 139900 | 195719 |

采用课程整段周期（包含初始化、核心执行及退出排空），而非只截取循环体：

\[
IPC_i=\frac{N_i}{C_i},\qquad
IPC_{geo}=\exp\left(\frac16\sum_{i=1}^{6}\ln IPC_i\right)
\]

相对收益为 `IPC_new / IPC_control - 1`。同一程序退休数不变时，也等于 `C_control / C_new - 1`。**六项几何平均不是将所有退休数除以总周期，也不是六项 IPC 的算术平均。**

每项先验证答案、每条退休指令的 PC／指令／寄存器写入／Store 信息，再比较原生 SystemVerilog 与 sv2v 转换模型的周期及退休日志。每个配置共374104条退休指令／模型。只有功能正确的配置才纳入性能分析。

本轮**不综合、不运行 ABC/STA**，没有新面积、Fmax 或评分；IPC 改善不等于实际时间改善，也不表示参数配置可以直接替换生产。

## 2. 基线与控制变量

默认基线为取指／译码／分配／提交 `4/4/4/4`、双 ALU、三 CDB、ROB32、PRF64、checkpoint64、I$ 1 KiB（16组×1路×64B）。D$ 固定8 KiB（128组×2路×32B），其余 RS、LSQ、RAS、预测／训练算法、AXI 和 Slave 保持同源。

| 对照组 | 改变的参数 | 固定条件与解释 |
|---|---|---|
| 分配宽度 | ISSUE=1/2/4 | FETCH2、DECODE4、COMMIT2、ALU2、ALU_CDB1、ROB32、PRF64、I$16组1路完全相同；不是直接拿默认四宽与资源不同的窄配置比较 |
| ROB | 16/32/64 | PRF固定96、其余默认四宽；checkpoint只随活跃身份预算自动调整，不改预测算法 |
| PRF | 64/96 | ROB固定32，其余默认不变 |
| I$ 容量 | 1/2/4 KiB | 1路、64B行，SETS=16/32/64，其余默认不变 |
| I$ 相联度 | 1/2/4路 | 总容量固定1 KiB，SETS=16/8/4，其余默认不变 |

改变相联度但保持容量时，组数和地址 index/tag 划分必然相应变化；此处比较的是等容量组织方式，不是保持组数同时扩容。I$ 4路使用树 PLRU，不是精确 LRU。本轮不对 D$ 容量或相联度作新结论。

### 4.1 vvadd：为什么 ROB16 比 ROB32 更快？

#### 测试条件与可信范围

固定 PRF96、取指／译码／分配／提交4宽、双 ALU／三 CDB、I$ 1 KiB、D$ 8 KiB、原有下一行预取及 SQ4／owner0 仲裁，复用原参数资格的两个配置、各自原生／sv2v模型。**只重链接外部 C++ 观察器，不重建或修改 RTL 模型，不改生产／两软件／正式指针。** 两份44 RTL快照中43份逐字节相同，唯一源码差异是 checkpoint 的初始容量检查；两种检查在本对照的checkpoint64下均为真，状态方程相同。ROB对应的恢复宽度仍为4／8，未假装它们也是相同参数。

课程条件仍采用从机服务延迟10：两模型分别复现 **3101／3740拍、4524条退休**。剔除新增逐拍记录后，原答案、九字段退休日志及 PASS 行逐字节保持；同配置两模型的全部新增记录也逐字节一致。另仅在 vvadd 上增加从机延迟1的固定诊断，不作为新的课程性能结果。

本节沿用原参数试验的模型与源码归属，不是对之后 warning 清理后的生产工作树重新作参数资格或 PPA 认证。画像共4次课程条件运行；低延迟另8次运行用于4个原观察器与4个画像观察器互相核对，没有重复原168次整核资格。重启后只核验既有产物并收口，未重复构建或仿真。

#### 差异发生在哪里

程序实际执行的是 `main` 中内联的300次向量加法循环 **PC 0xa8～0xc4**，之后执行300次结果校验循环0xd8～0xf0；不是未被调用的独立 `vvadd` 函数0x5c～0x88。以下按相同动态退休指令边界切分，区间为上一阶段最后一条退休后，到本阶段最后一条退休所在拍结束；退出阶段还包括总线排空。

| 阶段 | ROB16拍数 | ROB32拍数 | ROB32−ROB16 |
|---|---:|---:|---:|
| 启动及向量循环前准备 | 117 | 115 | −2 |
| **向量加法循环** | **1964** | **2606** | **+642** |
| 校验准备 | 3 | 2 | −1 |
| 结果校验循环 | 995 | 990 | −5 |
| 收尾及退出排空 | 21 | 26 | +5 |
| **逐拍观测合计** | **3100** | **3739** | **+639** |

观察器不记录初始第0拍，因此两个合计各比课程周期少同一个1拍；差值仍严格等于639拍。**主要差异在真正的向量加法阶段，不是结果校验或退出开销造成的假象。**

再按“冻结→flush→有退休→ROB空→队首就绪但阻塞→队首等待”优先级作互斥分类：

| 全程互斥周期类别 | ROB16 | ROB32 | 差值 |
|---|---:|---:|---:|
| **无退休且队首 Load 未就绪** | **1497** | **2177** | **+680** |
| 有退休 | 1414 | 1375 | −39 |
| 队首 ALU／乘除等待 | 14 | 12 | −2 |
| ROB空 | 122 | 122 | 0 |
| flush | 8 | 8 | 0 |
| 冻结 | 43 | 43 | 0 |
| 队首 Branch 等待 | 2 | 2 | 0 |
| **合计** | **3100** | **3739** | **+639** |

新增680拍队首 Load 等待中，等待已发送 miss 读返回的阶段增加616拍（755→1371），Cache查询等待增加134拍（411→545），其余 Load 子阶段合计减少70拍。这里是**实际执行轨迹的互斥记账**，不是宣称某一优化能独立消除680拍；有退休拍数也不等于退休指令数。

#### 排除两个直觉解释

- **不是更多分支误预测。** 两者均退休901条条件分支、其中7次误预测：启动分支1次、向量循环分支3次、校验循环分支3次，数据不匹配检查分支0次。恢复冻结反而由26降至19拍；退出后的冻结由17增至24拍，所以全程冻结均为43拍。不能把退化归因于“大ROB恢复更慢”。
- **不是直接越过 SQ≤4 的门槛。** ROB16／ROB32的旧态 SQ 峰值分别只有2／3项，`SQ>4` 拍数均为0。Load让行真实接受数反而为37／104；这说明实际仲裁时机改变，但更多让行事件并不自动带来更高 IPC，也不能据此判定该仲裁是唯一原因。

#### 已观察到的机制：更深窗口挤压预取准入时机

| 观测量 | ROB16 | ROB32 |
|---|---:|---:|
| 全程 ROB占用峰值 | 16 | 28 |
| 全程 LQ占用峰值 | 5 | 8 |
| 全程 LSU运输 owner峰值 | 3 | 6 |
| 向量阶段 D$ 8请求槽全部占用拍数 | 40 | 248 |
| **向量阶段真实预取入队** | **37** | **2** |
| 全程真实预取入队 | 76 | 41 |
| 全程由预取发起的行读 | 70 | 32 |
| 全程由需求发起的行读 | 83 | 121 |
| **全程行读总数** | **153** | **153** |

行读按 MSHR `readSent` 的真实置位跃迁核对旧owner／类型／line，且两配置读取的 **153个独立行地址完全相同**；不是把请求proposal当成真实发送。行读中的预取占比**不是预取命中率**。本例也不是“ROB32多取了很多行”或已证明的容量污染问题，而是**相同数据何时被取来、由谁触发、请求如何排队**发生了变化。

本实现预取入队要求：已有pending目标、**CPU当前没有原始请求proposal**、没有其他typed预取、D$请求占用≤6、MSHR占用≤2，并通过同行／Store组冲突检查。对向量阶段每一拍，已用旧请求行、MSHR、CPU proposal独立重算并匹配实际 `prefetchEnqueueInner`：

- ROB16的pending存在155拍，其中CPU有proposal118拍；另外37拍满足全部条件，实际入队37次。
- ROB32的pending存在149拍，其中CPU有proposal147拍；只有2拍满足全部条件，实际入队2次。
- pending期间请求占用>6的重叠计数为37／72拍；未入队就因该压力等条件清除pending的事件为37／72次。该计数与CPU proposal等条件可重叠，不能相加当成省拍数。

因此，“ROB更大只提供更多并行机会、其他行为不变”不适用于这里：额外窗口确实被使用，但更多在途工作改变了共享访存节奏；在本次轨迹中，ROB32几乎不给pending预取留下无CPU proposal的准入拍，许多原本提前触发的行读转为需求触发，队首Load等待随之增多。**预取准入受压这一环已由真实方程和事件验证；它解释了一个明确的性能耦合机制，但尚未证明它独占全部639拍差异。**

#### 一个固定低延迟对照

不改模型、RTL、程序或队列容量，仅将仿真 AXI Slave读／写响应的服务延迟参数从10改为1：

| 从机服务延迟 | ROB16周期 | ROB32周期 | 差值 |
|---|---:|---:|---:|
| **10：课程条件** | **3101** | **3740** | **639** |
| 1：仅诊断条件 | 2676 | 3017 | 341 |

低延迟下，答案与全部4524条九字段架构退休保持；原生／sv2v画像逐拍相同，画像观察器与原观察器在同延迟下剔除新增记录后逐字节相同。差距由639缩至341拍，进一步支持**对访存时序敏感**，但并未消失。该参数同时影响I／D流量和退出响应，不是只改变D$ miss延迟，更不是关闭预取的单机制消融；**不能把缩小的298拍直接称为预取贡献，也不能用此结果替换课程IPC。**

**结论：**当前证据支持“窗口加深→共享访存节奏与预取准入改变→关键Load等待增加”的解释，排除了额外误预测和直接触及SQ4门槛两个猜测。尚未做保持其他条件不变的预取关闭／独立节流消融，因而不宣称唯一根因、可独立回收拍数或通用最优ROB大小；也没有实现新的优化候选、综合、面积／频率结论或生产采用。

这一结果来自本轮新同源容量测量，不是复用历史其他微架构版本的数据，也不是由相联度试验推算。容量和相联度两组恰好得到相同周期，仍是不同组织与替换政策，不能宣称所有访问流等价。

## 7. 分配宽度：固定其他吞吐与容量

三点使用同一 `FETCH2/DECODE4/COMMIT2/ALU2/ALU_CDB1/ROB32/PRF64/I$1KiB` 控制组，仅改变 `CPU_ISSUE_WIDTH=1/2/4`。FQ/IQ仍各8项、checkpoint64，其余容量和协议保持。

| 程序 | 分配1宽 IPC | 分配2宽 IPC | 分配4宽 IPC |
|---|---:|---:|---:|
| median | 0.685138 | 0.804368 | 0.906026 |
| multiply | 0.837426 | 1.145977 | 1.222466 |
| vvadd | 0.953425 | 1.433006 | 1.129870 |
| towers | 0.802494 | 0.874710 | 0.884235 |
| qsort | 0.673782 | 0.828163 | 0.934161 |
| rsort | 0.921772 | 1.100336 | 1.114960 |
| **几何平均** | **0.805253** | **1.008627** | **1.023943** |
| 相对1宽 | — | +25.255892% | +27.157889% |

1→2宽六项均改善：vvadd +50.300919%、multiply +36.845160%、qsort +22.912720%，整体收益显著。

2→4宽几何 IPC只再提高1.518489%；median、qsort分别改善12.638292%、12.799145%，但 vvadd 从3157增至4004拍，IPC **-21.153846%**，抵消了大量收益。因此4宽不是逐程序最优，也没有线性翻倍效果。

此组用于隔离**顺序分配宽度**的影响。取指和提交均为2，两个 ALU 共享一条 ALU CDB，因此不能期望4分配就线性得到4 IPC；也不把此控制组与默认四宽三 CDB 直接作单变量比较。

该参数还选择本实现的窄／宽重命名和 ROB 路径，结论是这些实际配置的效果，不是抽象模型的理想宽度伸缩。共享资源、调度、恢复与投机访问流可能相互作用；本轮未采集对应停顿归因，不能断言 vvadd 退化的具体原因。

原资格矩阵中的一宽 ROB32/PRF80/2路 I$、二宽 ROB64/PRF96/4路 I$ 同时改变多项参数，只作为组合正确性结果，不能作为宽度敏感度结论。

## 8. 相对敏感度与取舍

用有限区间弹性辅助比较：`E = ln(IPC_geo,new / IPC_geo,old) / ln(parameter_new / parameter_old)`。它只描述该区间，不是全局导数；宽度组与其他组的控制条件不同，不能据此作跨组绝对性能排名。

| PRF64→96，ROB32 | 0% | 0 | 当前六项无额外收益 |
| I$容量1→2 KiB，1路 | +0.131453% | 0.001895 | 仅towers改善 |

就本轮数据而言，优先保证至少2宽分配比继续扩大 PRF 更有意义；ROB64/PRF96具有进一步评估的 IPC 价值；I$ 4路或4 KiB没有展示超过2路或2 KiB的额外收益。**这些只是后续研究建议，不是采用决定。** 若要比较实际吞吐、面积效率或评分，必须另获授权并对精确配置测量 PPA，不能拼接默认配置的频率／面积。
